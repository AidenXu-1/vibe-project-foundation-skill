# 路线图 / 里程碑

> 把大目标切成几个看得见终点的阶段。每个阶段都应有明确的「做完的标志」。

## 里程碑一览

| 里程碑 | 目标 | 做完的标志 | 状态 |
|--------|------|-----------|------|
| **M0 地基** | 仓库结构、文档骨架、AI 工作入口 | 三大文件夹 + Spec + Agent 规则 + git 安全网就位 | 🟡 进行中 |
| **M1 Spec v0** | 写清问题、用户、场景、边界和成功标准 | [spec.md](spec.md) 有可讨论的草案 | ⚪ 未开始 |
| **M2 风险检查** | 找出最大风险,决定是否先做原型或技术小实验 | 风险列表清楚,高风险点有验证计划 | ⚪ 未开始 |
| **M3 Spec v1** | 冻结 MVP 合同 | MVP 范围、技术路线草案、验收标准写入 [spec.md](spec.md) | ⚪ 未开始 |
| **M4 Kickoff** | 初始化 `app/` 和真实工程骨架 | 空项目能启动,命令和环境示例齐全,首次可运行验证通过 | ⚪ 未开始 |
| **M5 Build Loop** | 小步开发 MVP | 完成功能切片及相关验证；按需更新进度，按项目约定提交 | ⚪ 未开始 |
| **M6+ 长期维护** | 体验优化、增长功能、技术债治理 | 按改动范围沿用或更新 Spec，持续验证和维护 | ⚪ 未开始 |
